# How to Use Templates (For OSPO Staff)

## Context (Policy vs. Operational Structure)

Corporate Policy defines "what must be complied with, who is covered, and overall objectives," delegating specific procedures to Operational Guides.
These operational templates are customized to implement those policy requirements practically.

## Initial Implementation Stance

Uncertainty at the start is normal. Focus on identifying open questions, key internal collaborators, and required prep work.
We recommend releasing a minimal viable configuration and iterating based on feedback, rather than delaying launch for perfection (phased rollout).

## Defining Objectives First

Optimal customization depends on your primary goal. Deciding core priorities upfront ensures consistent decision-making:

Examples: Compliance-First / Security-First / Contribution & Release Promotion

### The Four Pillars of Governance

Organize customization topics into four pillars to ensure balanced coverage:

- Mission: Objectives and strategic vision for open source activities
- Incentive: Stakeholder motivations and value propositions
- Compliance: Legal, technical, and governance frameworks
- Engagement: Community participation models (Consume, Contribute, Release stages)

## Prioritized Customization Guide

### A. Essential Baseline Items (Implement First)

- Establish the primary documentation gateway ([[Company Name] Open Source Guide](./about/opensource-guide.md))
- Establish foundational guides ([About Open Source](./about/about-opensource.md) / [Benefits of Open Source](./about/benefits.md))
- Document practical workflows ([Using Open Source](./using/using-oss.md) covering discovery, evaluation, license checks, and integration)
- Discovery and inventory guides ([Finding Open Source Software](./using/finding-oss.md) / [Approved Internal OSS Inventory](./using/oss-inventory.md))
- Evaluation methodology ([Evaluating Open Source Software](./using/evaluation.md))
- Licensing guides ([Open Source License Compliance](./compliance/license-compliance.md) / [What Is a License?](./compliance/what-is-a-license.md) / [Types of Licenses](./compliance/license-types.md))
- Procurement workflows ([Procuring OSS from Suppliers](./using/supplier-procurement.md)) *High priority for organizations engaging contractors or joint development
- Help and reference resources ([OSS Usage FAQ](./using/usage-faq.md) / [Glossary](./about/glossary.md) / [What Is an OSPO?](./about/ospo.md))
- Initial incident and vulnerability reporting protocols
  - High priority due to policy compliance requirements
- Pre-release verification checklists (Essential for organizations distributing products or SaaS)

### B. Secondary / Phased Items (Implement After Baseline Operations Stabilize)

- Complex licensing guides ([Licenses with Source Code Disclosure Obligations](./compliance/source-disclosure-licenses.md) / [OSS with Commercial License Options](./compliance/oss-with-commercial-license-options.md))
  - -> Can be refined as issues arise, but early implementation is recommended for SaaS or software distribution models.
- Deepened licensing FAQs ([License FAQ](./compliance/license-faq.md) / NOTICE file creation)
  - -> Expand as operational cases accumulate.
- InnerSource practices ([What Is InnerSource?](./about/innersource.md))
  - -> Address when fostering internal open source culture becomes a priority.
- Open source release procedures
  - -> Postpone if not releasing proprietary code; implement early if publishing internal projects.
- Upstream contribution workflows
  - -> Implement when official business contributions begin (using blanket approvals to lower friction).
- Personal open source activity guidelines
  - -> Refine as employee personal open source engagement grows (focusing on NDAs, resources, and disclaimers).

## Designing Stakeholder Messaging

To drive template adoption, map out key approvers and address their specific concerns (compliance, security).
Prepare targeted messaging for each stakeholder group, collect operational feedback post-launch, and continuously refine FAQs and guides.
