# OSPOスターターキット　ドラフト版

本キットは、組織においてオープンソースプログラムオフィス（OSPO）を設立し、オープンソースの戦略的な活用と適切なガバナンス体制を構築するためのテンプレート集です。

## ⚠️ 開発ステータスと今後の予定

本キットは現在 **「ドラフト版（未完成）」** です。一部の内容は検討中または作成途中であり、今後大幅に更新される可能性があります。アップデートの状況については、後述の「更新履歴」を参照してください。

## 同梱ファイル一覧と概要

本キットには以下のドキュメントが含まれています。

### A. OSSポリシー（全社規定）テンプレート（`oss-policy-templates/`）

社内OSSポリシー（全社規定）を策定する際に参考となる条文サンプルと、その背景・カスタマイズ指針をまとめたテンプレートです。各条文は「条文サンプル」「解説」「カスタマイズの観点と運用上の留意事項」の3セクションで構成されています。

- `introduction.md`：はじめに ─ この文書の使い方
- `articles/00_preamble.md`：第0条前文
- `articles/01_purpose.md`：第1条目的
- `articles/02_definitions.md`：第2条用語の定義
- `articles/03_scope.md`：第3条適用範囲
- `articles/04_ospo.md`：第4条OSPO
- `articles/05_oss_usage.md`：第5条OSSの利用
- `articles/06_contribution.md`：第6条OSSプロジェクトへのコントリビューション
- `articles/07_oss_release.md`：第7条当社著作物のOSSとしての公開
- `articles/08_personal_oss_activity.md`：第8条従業員の私的OSS活動
- `articles/09_trademark_and_brand.md`：第9条商標およびブランドの取扱い
- `articles/10_license_violation_incident.md`：第10条ライセンス違反およびインシデントへの対応
- `articles/11_security_and_vulnerability.md`：第11条セキュリティおよび脆弱性対応
- `articles/12_records_and_reporting.md`：第12条記録および報告
- `articles/13_education_and_awareness.md`：第13条教育および啓発
- `articles/14_employment_rules_relation.md`：第14条就業規則等との関係
- `articles/15_revision_and_enforcement.md`：第15条改定および施行


### B. 運用テンプレート（`operation-templates/`）

社内ポータルサイト（WikiやSharePoint等）に掲載し、担当者に周知するためのドキュメントテンプレートです。各テンプレートに「カスタマイズチェックリスト」「カスタマイズガイド（コメント内）」を記載しています。

テンプレートの導入・カスタマイズ手順については、`how-to-use-templates-for-ospo.md`（OSPO担当者向け）および `how-to-use-guide-for-users.md`（利用者向け）を参照してください。

- **基礎・組織**（`about/`）
  - `opensource-guide.md`：オープンソースガイド（入り口）

  - `ospo.md`：OSPOとは
  - `innersource.md`：インナーソースとは
  - `glossary.md`：用語集

- **ライセンスコンプライアンス**（`compliance/`）
  - `license-compliance.md`：オープンソースライセンスコンプライアンス
  - `what-is-a-license.md`：ライセンスとは
  - `license-types.md`：ライセンスの種類
  - `source-disclosure-licenses.md`：ソースコード提供義務のあるライセンス
  - `oss-with-commercial-license-options.md`：商用ライセンスが選択できるOSS
  - `license-faq.md`：ライセンスFAQ

- **実務・OSS活用**（`using/`）
  - `using-oss.md`：OSSを使う
  - `finding-oss.md`：OSSの探し方
  - `oss-inventory.md`：社内導入済みOSSリスト

  - `supplier-procurement.md`：サプライヤーからのOSS入手手順
  - `usage-faq.md`：OSS利用FAQ

## コントリビューションガイドライン（暫定）

運用しながら随時アップデートしますが、当面は以下を目安とします。

- 大きな構造変更や方針変更は、まずIssuesで相談しましょう。
  - 例：ディレクトリ構成の変更、テンプレートの大幅な書き換え、運用ルールの変更 等
  - 改善提案は背景・期待する効果を明記してください。
- 小さな修正（誤字脱字、軽微な表現調整）はそのままPull Request(以下、PR)して構いません。
- PRのタイトル・説明には、できるだけ「なぜそうするのか」を簡潔に記載してください。
  - コミットタイトルに [add], [fix], [update] などのタグを先頭に付けることを推奨します。
- PR対応
  - 1名以上のレビューを経てマージすることとします。
  - テストやリンターなど、自動レビューが成功していることを確認することとします。

## 対応目安（SLA: Service Level Agreement）

運営側は、以下の方針を目安として、Issue / Pull Requestへの対応を行います。

### 対応時間の目安

- Issue への一次対応
  - 原則として **1〜2週間以内** にコメントまたはラベル付与を行うこととします。
- Pull Request のレビュー
  - 原則として **2週間以内** にレビューまたは進捗コメントを行うこととします。

上記はあくまで目安であり、時期や状況により遅れる可能性があります。

### 対応範囲の考え方

運営側は、主に以下のような項目を対応対象とします。

- テンプレートの内容や構成に関する変更・改善
- 用語の統一や表現の整理
- OSPOスターターキットの全体方針・位置づけに関する調整

一方、以下の内容は原則として **運営側のSLA対象外** とします。

- 各組織ごとの固有事情に踏み込んだ個別コンサルティング
- 本リポジトリ外のシステム設定やネットワーク、認証周りのトラブルシュート
- OSPO以外の全社制度・ガバナンス設計そのものの承認・決裁
- その他、テンプレートの内容に関連のない事柄

### 営業日・対応時間の前提

- 営業日は **平日（日本時間）** を前提とします。
- 繁忙期やイベント対応期間などは、上記の目安より遅れる場合があります。

### SLA の位置づけ

- ここで示す内容は、あくまで「運営側として目指す対応の目安」であり、必ずしも法的拘束力のあるサービス保証を行うものではありません。
- 実際の運用状況やリソースに応じて、SLAの内容は見直し・更新する可能性があります。
